## Architecture Overview

### Technology Stack

The tool is a dependency-free static web application built with:

- **HTML5** - Single-page application structure
- **CSS3** - Styling via external stylesheet (`/tools/power-supply-troubleshooter/css/style.css`)
- **Vanilla JavaScript (ES6)** - All logic in a single file (`/tools/power-supply-troubleshooter/js/app.js`)

No frameworks, libraries, or build tools are used. The tool requires no server-side processing or database.

### File Structure

```
/tools/power-supply-troubleshooter/
├── index.html          # Main HTML document
├── css/
│   └── style.css       # All visual styling
└── js/
    └── app.js          # Application logic, data, and rendering
```

### Component / Logic Breakdown

The application consists of three logical layers:

1. **Data Layer** - The `TREE` constant object containing all question nodes, options, and result definitions
2. **Rendering Layer** - The `render()` and `showResult()` functions that generate HTML dynamically
3. **Navigation Layer** - Event handlers for option buttons, back button, and restart button

The tool uses a stack-based navigation pattern where user choices traverse a predefined decision tree. Each node in the tree represents either a question (with multiple choice options) or a terminal result (with diagnostic actions).

## Data Schemas

### `TREE` Object (Decision Tree)

The `TREE` constant is the core data structure. It is a flat object where each key is a node identifier string.

**Node Identifier Format:** `snake_case` strings (e.g., `no_start`, `voltage_issue`, `too_fast`)

**Root Node:** `start`

**Node Object Schema:**

```javascript
{
  "q": "string",           // Question text displayed to user
  "opts": [                // Array of option objects (required)
    {
      "icon": "string",    // Emoji or text icon (e.g., '🔌', '✅', '⚡')
      "text": "string",    // Primary option label
      "sub": "string",     // Secondary description text (optional)
      "next": "string|null", // Node identifier to navigate to, or null for terminal
      "result": {          // Present only when next is null (terminal node)
        "level": "string", // One of: 'ok', 'check', 'service', 'stop'
        "icon": "string",  // Result icon (e.g., '🛑', '✅', '🔧')
        "verdict": "string", // Short diagnosis title
        "sub": "string",   // Detailed explanation
        "actions": [       // Array of action strings
          "string"
        ]
      }
    }
  ]
}
```

**Example Node (non-terminal):**

```javascript
"no_start": {
  "q": "Is the power supply unit showing any indicator lights?",
  "opts": [
    {
      "icon": "⚫",
      "text": "No lights at all, completely dead",
      "next": "no_start_dead"
    },
    {
      "icon": "🟢",
      "text": "Power LED is on but machine does not respond",
      "next": "no_start_psu_ok"
    },
    {
      "icon": "🔴",
      "text": "Error light or blinking indicator",
      "next": null,
      "result": {
        "level": "service",
        "icon": "⚠️",
        "verdict": "Power supply error state",
        "sub": "Consult the PSU manual for your blink code",
        "actions": [
          "Note the exact blink pattern (count of flashes)",
          "Look up the error code in your PSU manual or manufacturer website",
          "If no manual available, try a full power cycle (unplug 30 s, replug)",
          "If error persists after power cycle, the PSU likely needs replacement or repair"
        ]
      }
    }
  ]
}
```

### `DEPTHS` Object

Generated by the `depth()` function. Maps each node identifier to its depth level (integer) from the root.

```javascript
{
  "start": 0,
  "no_start": 1,
  "no_start_dead": 2,
  "no_start_psu_ok": 2,
  "foot_pedal": 3,
  // ... etc.
}
```

### `stack` Array

A simple array of node identifier strings representing the user's navigation path. Used for the back button functionality.

```javascript
["start", "no_start", "no_start_psu_ok"]
```

## Calculation / Logic Algorithms

### `depth()` Function

**Purpose:** Calculates the depth of every node in the decision tree from the root node (`start`).

**Algorithm:**

1. Initialize an empty `counts` object
2. Define a recursive inner function `count(id, d)` that:
   - Returns immediately if `id` is not in `TREE`
   - Sets `counts[id] = d`
   - For each option in `TREE[id].opts`, if `o.next` exists and has not been counted yet, recursively call `count(o.next, d + 1)`
3. Call `count('start', 0)`
4. Return the `counts` object

**Complexity:** O(N) where N is the number of nodes in the tree.

### `MAX_DEPTH` Calculation

After `depth()` runs, `MAX_DEPTH` is set to the maximum value in the `DEPTHS` object:

```javascript
const MAX_DEPTH = Math.max(...Object.values(DEPTHS));
```

This value is used to calculate the progress bar percentage.

### Progress Bar Percentage

Calculated in the `render()` function:

```javascript
const pct = Math.round((d / (MAX_DEPTH + 1)) * 100);
```

Where `d` is the current node's depth. The `+1` accounts for the fact that the root node is depth 0 and there is typically one additional step beyond the deepest node (the result).

### `render(nodeId)` Function

**Purpose:** Renders the current question or result view into the DOM.

**Algorithm:**

1. Look up the node from `TREE` using `nodeId`
2. Get the node's depth from `DEPTHS`
3. Calculate progress percentage
4. Build HTML string with:
   - Progress bar showing "Step X of ~Y"
   - Question text
   - Option buttons (each with icon, text, and optional sub-text)
   - Back button (only if `stack.length > 0`)
5. Set `wizard.innerHTML` to the generated HTML
6. Attach click event listeners to each option button that:
   - Get the option object from `node.opts[parseInt(btn.dataset.idx, 10)]`
   - If `opt.result` exists, call `showResult(opt.result)`
   - If `opt.next` exists, push current `nodeId` to `stack` and call `render(opt.next)`
7. Attach click listener to back button that pops the last node from `stack` and calls `render(stack.pop())`

### `showResult(r)` Function

**Purpose:** Renders a terminal result view with verdict, explanation, and action items.

**Algorithm:**

1. Build HTML string with:
   - Result banner showing level-specific styling (`level-${r.level}`), icon, verdict, and sub-text
   - Actions list rendered as an unordered list
   - Restart button
2. Set `wizard.innerHTML` to the generated HTML
3. Attach click listener to restart button that resets `stack` to empty array and calls `render('start')`

## API Reference

The tool exposes no public API. All functions are module-scoped within `app.js` and are not accessible from outside the script.

### Internal Functions

| Function | Parameters | Returns | Description |
|----------|------------|---------|-------------|
| `depth()` | None | Object | Calculates depth of all nodes in the decision tree |
| `render(nodeId)` | `nodeId` (string) | `undefined` | Renders the question or result view for the given node |
| `showResult(r)` | `r` (result object) | `undefined` | Renders a terminal result view |

### Internal Variables

| Variable | Type | Description |
|----------|------|-------------|
| `TREE` | Object | Decision tree data structure |
| `wizard` | HTMLElement | DOM reference to `#wizard` container |
| `stack` | Array | Navigation history for back button |
| `DEPTHS` | Object | Pre-calculated node depths |
| `MAX_DEPTH` | Number | Maximum depth value |

### Standalone Embedding

### Iframe Embedding

The tool supports iframe embedding with automatic dark/light theme detection. When loaded in an iframe, the tool:

1. Sets `data-theme` attribute to `"dark"` by default
2. Listens for `message` events of type `poli-theme` to switch between light and dark themes

**Example embed code:**

```html
<iframe 
  src="https://poliinternational.com/tools/power-supply-troubleshooter/" 
  width="100%" 
  height="600" 
  frameborder="0"
  title="Tattoo Machine Power Supply Troubleshooter">
</iframe>
```

**Theme control from parent page:**

```javascript
// Switch to light theme
document.querySelector('iframe').contentWindow.postMessage({
  type: 'poli-theme',
  light: true
}, '*');

// Switch to dark theme
document.querySelector('iframe').contentWindow.postMessage({
  type: 'poli-theme',
  light: false
}, '*');
```

## Customization

### Modifying the Decision Tree

To add, remove, or modify questions and results, edit the `TREE` constant in `js/app.js`. Each node must follow the schema documented above. After changes:

- The `depth()` function automatically recalculates depths
- The progress bar adapts to the new tree structure
- No other code changes are required

## Performance

- **Bundle size:** Minimal (single HTML file, single CSS file, single JS file)
- **Network requests:** 3 total (HTML, CSS, JS)
- **DOM manipulation:** Only the `#wizard` container is modified; no reflows on other elements
- **Memory usage:** The `TREE` object is the primary memory consumer; approximately 15KB of JSON data
- **Rendering:** All rendering is synchronous; no async operations or timers
- **No external resources:** No fonts, images, or third-party scripts loaded

## Security

### Input Handling

The tool accepts no user input fields (no text inputs, no forms, no URL parameters). All user interaction is through button clicks with predefined option values. This eliminates the risk of:

- Cross-site scripting (XSS) via user input
- SQL injection (no database)
- Command injection (no server-side execution)

### Message Events

The tool listens for `message` events from the parent window when embedded in an iframe. It only processes messages with:

- `e.data.type === 'poli-theme'`
- `e.data.light` boolean value

All other messages are ignored. The tool does not evaluate or execute any code from received messages.

### Content Security

The HTML includes a `<meta name="robots" content="noindex, nofollow">` tag to prevent search engine indexing of the tool page itself (though the tool is accessible via the live URL).

### No External Dependencies

The tool loads no external scripts, stylesheets, fonts, or images. This eliminates supply chain security risks from third-party resources.
